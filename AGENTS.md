# Hideout Coffee POS

## Stack

- **Laravel 12** + MySQL (`hideout_coffe`), session/queue/cache all `database` driver
- **Blade** (`@yield` section pattern) + **Tailwind v3** (PostCSS, NOT `@tailwindcss/vite`) + **Chart.js** (CDN) + **Alpine.js** + **Preline UI**
- **Spatie RBAC**: 2 roles — `owner`, `kasir`; role middleware aliased in `bootstrap/app.php:17`
- **No API routes**; web-only (routes in `routes/web.php`, which `require`s `routes/auth.php`)

## Dev commands

| Action | Command |
|--------|---------|
| Full stack | `composer dev` (artisan serve + queue:listen + pail + Vite via concurrently) |
| PHP tests | `php artisan test` |
| Single test | `php artisan test --filter=TestName` |

## Key architecture

- **Owner** (`/owner/*`, `role:owner`): `Owner\DashboardController` (invokable), CategoryController, MenuController, CashierController, PromoController (all `Route::resource`), and `Owner\TransactionController` with **manual** routes (index, create, store, show, `kasirShow`, history, `page` with `?tab=create|history`, cancel, loadMoreMenus, plus JSON `index-filter`/`history-filter` (return `{html, stats}`) and `chart-filter` (returns `{labels, values}`), `receipt-pdf`, and `print-index` → `GET /transactions/print`, renders `owner.transactions.print` as an A4-landscape DomPDF report of the filtered index). `index`/`indexFilter`/`printIndex` all build the same filtered query via `transactionsQuery()`, and `index`/`indexFilter` render the shared `owner.transactions._data_table` partial. Resources also get `toggle-status` PATCH routes (menus, cashiers, promos). **Note:** owner's `history()`/`historyFilter()` render the **kasir** views (`cashier.transactions.history`, `cashier.transactions._history_table`), scope to `Auth::id()`, and flip links via `$isOwner` — the shared `_history_table` Detail links owners to **`owner.transactions.kasir-show`** (`kasirShow()` renders `cashier.transactions.show`) and kasir to `kasir.transactions.show`. Edit one and you change both. ⚠ `page()`'s local history tab is **not** that partial: it's a separate inline table inside `owner.transactions.page` (same `Auth::id()` scope, hardcoded owner routes) — edits to `_history_table` don't propagate there, keep them in sync manually. Owner's `index()` is the exception: global stats and a cashier filter of `User::role(['kasir','owner'])`. `owner.kasir.dashboard` (`GET /owner/kasir-dashboard`) reuses `Cashier\DashboardController` + the `cashier.dashboard` view (owner-aware) — the owner's kasir-mode landing page (header "Halaman Kasir", nav-kasir "Dashboard" tab), NOT the admin `owner.dashboard`.
- **Kasir** (`/kasir/*`, `role:kasir`): `Cashier\DashboardController` (invokable) and `Cashier\TransactionController` (create, store, cancel, history, show, loadMoreMenus, `history-filter`, `receipt-pdf`). **Views live in `resources/views/cashier/`** — the old `views/kasir/` dir is gone. (`owner/cashiers/*` views are the kasir-account *management* pages, unrelated.)
- **Owner `show()`** has **no** `user_id` ownership guard on transactions, but **`Cashier\TransactionController::show()`/`cancel()` DO** (403 if not the kasir's own) — mirror this if you add mutual features
- **Auth**: login uses `username` (in `app/Http/Requests/Auth/LoginRequest.php`), status check + role redirect in `AuthenticatedSessionController::store()` (`status === 'inactive'` → logout + error; `hasRole('owner')` → `owner.dashboard`, `hasRole('kasir')` → `kasir.dashboard`). Forgot-password/reset (Breeze) still authenticate by `email`
- **User model**: `username`, `first_name`, `last_name`, `email`, `phone`, `password`, `status` — `HasRoles` trait; `name` column does not exist
- **Menu `code`**: nullable unique column (migration `2026_08_28_..._add_code_to_menus_table`), auto-set on create via `Menu::generateCode()` → `{CAT-INITIALS}-###` (unique per category, keeps counting). Menu index orders by code. Codes are reindexed (`Menu::reindexCodes()`) when a menu is deleted or moved to another category (MenuController does both in `update()`/`destroy()`).
- **Invoice**: `Transaction::getCodeAttribute()` computes `TRX-####` + `-XX` suffix (first 2 chars of each unique category name), e.g. `TRX-0003-KO-NO` — derived, NOT a stored column. ⚠ The suffix only appears when the `items` relation is loaded (`getCodeAttribute()` checks `relationLoaded('items')`), so `$transaction->code` is just `TRX-####` without eager-loaded items
- **Layouts**: `layouts.app` (`@yield`, Inter, `lang="id"`, sidebar+header; includes `layouts.part.sidebar-kasir` vs `sidebar` by role). `layouts.app-nosidebar` is the **kasir POS chrome** (header-kasir + collapsible `nav-kasir` top bar, no sidebar) — used by kasir dashboard/create/history/show AND `owner.transactions.create`. ⚠ `owner.transactions.page` (the tabbed POS) extends `layouts.app` (sidebar variant), NOT `app-nosidebar`. `layouts.guest` (Figtree, `{{ $slot }}`)
- **Root `/`** redirects by role or to login
- **Seed users**: 3 accounts, all `password` — `mhdhsbyy` (kasir), `zein` (kasir), `daniel` (owner, the only one). `daniel` is used by `MenuStoreProbeTest`. `UserSeeder` `delete()`s username `hasby` and re-creates the rest via `updateOrCreate`.
- **Profile page** (both roles share it, `auth`-only, outside `owner.`/`kasir.` groups): routes `profile.edit`/`profile.update` → `ProfileController`; view `resources/views/profile/edit.blade.php` extends `layouts.app` **unless the user is in kasir mode** — `profile/edit.blade.php` picks the layout itself: kasir role always → `layouts.app-nosidebar`, and owner → `app-nosidebar` when arriving via `?from=kasir` (carried by the header-kasir dropdown's Profil link and preserved on update redirect) so an owner browsing the kasir POS keeps the header-kasir + nav-kasir chrome instead of the sidebar. Edits `username`/`first_name`/`last_name`/`email`/`phone` (validated by `ProfileUpdateRequest`, unique username+email ignoring self; `last_name`/`phone` optional). Avatar photo is changed from the **top Account Summary card** via a **separate** route `profile.photo` → `ProfileController::updatePhoto()` (uploaded to `public` disk `avatars/`, old deleted on replace; validated `image, mimes:jpg/jpeg/png/webp, max:2048` with Indonesian messages; auto-submits on file select, `back()` keeps `?from=kasir`, `users.photo` column from migration `add_photo_to_users_table`). `User::avatar_url` falls back to `images/logo-ho.png` when unset — use it in avatars instead of hardcoding the logo. Password form posts to `password.update` (`PasswordController`, validates with `updatePassword` error bag). `profile.destroy` route exists but no UI button. Old Breeze partials + `delete-user-form` were removed; the header dropdown and the **kasir** sidebar (not the owner sidebar) link `profile.edit`.

## POS / discounts

- **3 discount layers**: (1) per-item flat discount, (2) manual transaction discount, (3) auto-applied promos (percentage/flat, scoped to item/category/transaction, with `start_date`/`end_date` datetime range — migration `2026_09_20_..._make_promos_dates_datetime` — plus `min_quantity`/`min_amount` gates)
- **Promo logic is duplicated across 5 files — keep in sync**: Alpine `posApp()` in `cashier.transactions.create`, `owner.transactions.create`, and `owner.transactions.page`, plus server recalc in BOTH `Cashier\TransactionController::store()` and `Owner\TransactionController::store()` (server revalidates via `Promo::active()`; server wins)
- `store()` returns `ReceiptBuilder::toResponse()` (PDF) directly when the hidden `print_receipt` input is `'1'`; otherwise it redirects back with a `success` flash (shown as a Swal toast)
- **Receipts = PDF only** (`barryvdh/laravel-dompdf`): `App\Support\ReceiptBuilder::toResponse()` renders `views/pdf/receipt.blade.php` on 80mm thermal paper — DomPDF has no content-height API, so it binary-searches the smallest single-page height. Route `transactions.receipt-pdf` exists on BOTH owner & kasir. Kasir's `receiptPdf()`/`show()`/`cancel()` all require `transaction.user_id === Auth::id()` (403) — owner's do not. ⚠ **Two separate PDF code paths**: receipts go through `ReceiptBuilder`, but `Owner\TransactionController::printIndex()` spins up a **raw `new Dompdf`** (A4-landscape report, `laporan-transaksi-*.pdf`) — mirror that, don't route the report through ReceiptBuilder
- Cart/promos are posted as **JSON strings** in hidden form inputs (`JSON.stringify(...)`); `store()` detects strings and `$request->merge(json_decode(...))` before validating
- Payment methods: `cash, debit, kredit, qris` (`card` was renamed → `kredit` by migration `2026_09_21_..._rename_card_payment_method_to_kredit`; debit & kredit share the EDC modal). **QRIS** shows a modal with `public/images/qris.jpeg` and forces `amount_paid = total` on submit
- **`load-more`**: POS views fetch `transactions.load-more-menus` (paginate 8) → JSON `{ html, hasMore }`. `menus.load-more` (paginate 12) exists but no view calls it — and it's registered AFTER `Route::resource('menus', ...)`, so `GET /owner/menus/load-more` is swallowed by the `menus/{menu}` show route (404). Same risk on `transactions/{transaction}`: `receipt-pdf` and `load-more-menus` are registered before the show route on BOTH owner & kasir — keep it that way. Register any new literal route BEFORE its resource.

## Frontend conventions

- **Custom Tailwind colors** (use these in new views): `primary` (#764706), `secondary` (#ADA68A), `soft` (#FFF0DA), `light` (#F1F1F1), `dark` (#191919) — defined in `tailwind.config.js`
- **Fonts**: `Inter` for main layout (`font-inter`, loaded in `layouts.app`), `Figtree` as default sans (loaded from Bunny Fonts in `layouts.guest` only — won't resolve on app pages unless cached by a prior guest visit)
- **Chart.js**, **SweetAlert2**, **animate.css** loaded from CDN in BOTH `layouts.app` and `layouts.app-nosidebar`; **anime.js is only loaded in `layouts.app`** (the POS chrome doesn't need it). Not via npm.
- **Alpine.js** powers interactive views (POS cart, sidebar toggle) — inline `<script>` blocks, not compiled
- **Global JS helpers** (duplicated, defined in BOTH `layouts.app` and `layouts.app-nosidebar`): `confirmDelete(form, message)` / `confirmCancel(form, message)` (SweetAlert2 confirmation → `form.submit()`), `blockedDelete(message)` (auto-dismiss error toast), `confirmLogout(form, message)` (also clears `pos_cart`/`pos_state` localStorage before submit), `hoCountUp(target, options)` (Alpine-compatible animated counter with `id-ID` locale formatting)
- **Code style**: 4-space indent (default, applies to PHP/Blade/JS), 2-space (YAML only), LF line endings — see `.editorconfig`; PHP lint via `./vendor/bin/pint`

## Quirks & gotchas

- **Uncommitted WIP (repo has a single commit `e793bc2 "first"`)**: almost the entire app is uncommitted — kasir views moved to `resources/views/cashier/`, the `menus.code`/`users.photo`/`promos-datetime`/`card→kredit` migrations, `App\Support\ReceiptBuilder` + `views/pdf/receipt.blade.php`, `app/Console/Commands/GenerateMenuThumbnails.php`, `public/images/qris.jpeg`, `owner.transactions.print`/`_data_table` + `kasirShow`, and the whole `owner.kasir.dashboard`/kasir-POS feature set. A fresh clone has none of it; after pulling run `php artisan migrate`.
- **⚠ Tests wipe the dev DB**: `phpunit.xml` has the SQLite env vars commented out, so `php artisan test` runs against MySQL `hideout_coffe` and the auth tests use `RefreshDatabase` → running tests **destroys your dev data**. They're also broken against the real schema: `UserFactory` defines `name` (column gone), and `AuthenticationTest`/`RegistrationTest`/`ProfileTest` still login/post by `email` or `name` and assert `route('dashboard')` (should be `username`, `owner.dashboard`/`kasir.dashboard`). Uncomment the SQLite env to test safely.
- **`MenuStoreProbeTest` needs seeded data**: does NOT use `RefreshDatabase` — it queries the live dev DB for user `daniel` (`firstOrFail`) and dumps HTML to STDERR. Run it only against a seeded DB (`migrate:fresh --seed`).
- **Registration broken**: `RegisteredUserController` validates/creates `name` (column gone), `resources/views/auth/register.blade.php` does not exist
- **Dead layout code**: `layouts/default/` directory is unused — do not import from it. `navigation.blade.php` (in `layouts/`) is also dead — references `Auth::user()->name` (column gone) and `route('dashboard')` (doesn't exist)
- **Tailwind v3 only**: `postcss.config.js` uses `tailwindcss` + `autoprefixer`. `@tailwindcss/vite` (v4) is in `package.json` but NOT wired in `vite.config.js`. Do not use v4 syntax (`@import "tailwindcss"`, CSS-first config)
- **⚠ `php artisan view:clear` breaks the Vite/Tailwind build**: `tailwind.config.js` used to scan `./storage/framework/views/*.php` (Laravel's compiled-view cache); once it's emptied the CSS build dies with `ENOENT ... storage/framework/views/*.php` and **no Tailwind styles apply** until you re-run `view:cache`. That glob is now removed — don't re-add it. If CSS ever stops applying after clearing views, run `php artisan view:cache` (or restart `npm run dev`).
- **Preline** imported in `resources/js/app.js` — initializers must run after DOM mutations; may conflict with Alpine
- **Kasir dashboard**: `Cashier\DashboardController` renders `cashier.dashboard` (stat cards for **today**: txns + revenue, 7-day revenue chart, top-5 products + 5 recent transactions — today's txns/revenue, the chart, and the 5 recent transactions are scoped to `user_id = Auth::id()`; top-5 products and the active-menu count are **global** across all completed transactions). Sidebar: `layouts.part.sidebar-kasir` (dashboard, transaksi, riwayat only); `layouts.app` includes the correct one by role. The view is **owner-aware** (`$isOwner`) and shared: the owner reaches it via `owner.kasir.dashboard` ("Halaman Kasir" / nav-kasir "Dashboard" tab), not `owner.dashboard`.
- **Inline Chart.js script** in both layouts initializes `#chart` on every page load on raw DOM, independent of Alpine — watch for duplicate instances if you add charts. (`#produkChart` logic exists in `layouts.app` but **no view renders that canvas** — the "Produk Terlaris" dashboards are CSS bars, not Chart.js; the block is dead.) ⚠ CDN order differs: in `layouts.app` Chart.js loads BEFORE `@stack('scripts')`; in `layouts.app-nosidebar` it loads AFTER — so a `@push('scripts')` block using `Chart` breaks in the no-sidebar chrome.
- **Menu photo storage**: `storage/app/public/menus/{category-slug}/` via `public` disk; old photos deleted on update/destroy (menu seeded photos use category initials for each category). Views always render `$menu->thumb_url` — a **WebP thumbnail** auto-generated by a `Menu::saved` hook (`app/Console/Commands/GenerateMenuThumbnails.php`, requires GD+WebP ext). `getThumbUrlAttribute` falls back to the original if the thumb is missing. Regenerate all with `php artisan menus:thumbnails`.
- **`.env.example` diverges from `.env`**: `.env.example` defaults to SQLite + `APP_LOCALE=en` vs `.env`'s MySQL + `APP_LOCALE=id` — fresh clones must update
- **Indonesian locale**: `APP_LOCALE=id`, auth/validation messages in Bahasa
- **Seeder order matters**: `DatabaseSeeder` runs `UserSeeder` first (it creates the `owner`/`kasir` roles) — keep it first, other seeders depend on roles+categories. Note `TransactionSeeder` **is** wired into `DatabaseSeeder` (5th) and `delete()`s all transactions before re-seeding.
- **No CI**: no `.github/` directory
- **Slow `composer dev` on Windows**: the PHP built-in server (`artisan serve`) recompiles files every request and is very slow without OPcache (~1.3–2s TTFB even for a bare `/up`, which is why POS menu cards appear "slow" — the whole page response is slow, not the query (0.06s) or the 16–20KB webp thumbs). Fix: `zend_extension=opcache` + `opcache.enable_cli=1` in `C:\xampp\php\php.ini` (`php --ini` to find it), then restart `composer dev`. Warm `/up` drops ~1.3s → ~0.25s.
